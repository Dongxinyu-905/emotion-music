# MoodTune · 基于人脸情绪识别的歌曲推荐系统

HTML5 + CSS3 + 原生 JavaScript（ES Module）+ **Vue 3**，无构建步骤。
情绪识别 **完全在本机浏览器内运行**（本地模型权重，无云端请求）；曲库为 **本地 8 首 MP3 + 在线歌曲 API**。

---

## 一、快速开始

> 必须通过 **HTTP 服务**访问（`file://` 下浏览器会拦截模型文件与 ES Module 的加载）。

Windows 双击 `start.bat`，或命令行：

```bash
cd emotion-music
python -m http.server 8123 --bind 127.0.0.1
# 浏览器打开 http://127.0.0.1:8123/
```

其他方式：`npx serve .`、`php -S 127.0.0.1:8123` 均可。
摄像头需要 `localhost` / `https` 环境（`127.0.0.1` 已被浏览器视为安全上下文）。

### 演示流程

1. 页面下方「演示人脸」有 8 张 AI 生成的写实人脸（7 种情绪 + 1 张双人），点击任意一张即可自动识别并出歌单。
2. 也可以点「开启摄像头」做实时识别，上传自己的图片，或切到「打开视频」点 **载入示例视频**
   （8 秒，开心→悲伤→惊讶，可以看到歌单随情绪自动切换），也可以选自己的视频 / 用 3 秒倒计时拍照。
3. 右上三个策略切换歌单走向：**共情陪伴 / 温和疗愈 / 提振激励**。
4. 歌单里可播放、拖动进度、点赞/不喜欢（会即时影响后续推荐）。

## 三、情绪识别算法（全本地）

### 1. 人脸检测
TinyFaceDetector（SSD + MobileNet 轻量化主干），输入 416×416，置信度阈值 0.32，单次前向可检出多张人脸并回归边界框。

**多尺度补检**：该检测器对占画面 80% 以上的正脸特写容易漏检。原始尺寸 0 检出时，把画面居中放进
1.8×、2.6× 的留白画布（相当于降低人脸的相对尺寸）重试，再把框与关键点坐标做逆变换回原图。

### 2. 关键点回归
68 点人脸关键点模型，输出眉、眼、鼻、唇、下颌轮廓坐标，供几何层计算与界面可视化使用。

### 3. CNN 表情分类（主判据，权重占比 0.72）
FaceExpressionNet：轻量卷积网络，在 FER+ / AffectNet 类人脸表情数据上训练，
输出 7 类 softmax 概率：`neutral / happy / sad / angry / fearful / disgusted / surprised`。
权重为 uint8 量化（约 3.4 MB），随项目存放于 `models/`，通过 TensorFlow.js（WebGL 后端）本地推理。

### 4. 几何规则引擎（辅助 + 降级，权重占比 0.28）
以瞳距 `d` 归一化，计算 7 个**尺度不变**的几何量（对应 FACS 动作单元）：

| 特征 | 计算式 | 含义 |
|---|---|---|
| `mouthOpen` | ‖p62 − p66‖ / d | 张口度（AU26） |
| `mouthWide` | ‖p48 − p54‖ / d | 唇宽（AU12 横向） |
| `cornerUp` | (y51 − (y48+y54)/2) / d | 嘴角上扬（AU12），>0 为微笑 |
| `browRaise` | (ȳ37,38,43,44 − ȳ19,24) / d | 眉眼距（AU1+2） |
| `innerBrow` | (ȳeyeTop − ȳ21,22) / d | 眉心上抬（AU1+2 内侧） |
| `eyeOpen` | (EAR_L + EAR_R)/2 | 眼睛开合（AU5） |
| `mouthRound` | mouthOpen / mouthWide | 唇形圆度（MAR，惊讶时嘴变圆） |

> 原型值 `μ_c,k` 不是凭感觉写的：先用人脸标定集统计各情绪下的实际读数，再结合 FACS 动作单元定义确定；
> 容差 `σ_k` 按标定集散度设定（如 `cornerUp` 的 σ 仅 0.030，因为该维判别力最强也最敏感）。

高斯核最近原型分类：

```
s_c = − Σ_k  w_k · ( (f_k − μ_c,k) / σ_k )²
P_geo(c) = softmax( s_c / T ),  T = 2.6
```

其中 `w` 为各维判别力权重（嘴角上扬 3.20、唇宽 1.60、张口 1.60、唇形圆度 1.80、
眉心上抬 1.10、眉眼距 0.90、眼睛开合 0.70）。

### 5. 双层融合（权重自适应）

```
w_geo = 0.10 + 0.30 · (1 − max P_CNN)        # CNN 越不确定，几何层话语权越大
若 max P_geo > 0.93: w_geo ≥ 0.38            # 出现强动作单元证据（如明显 AU12 微笑）
w_geo ≤ 0.42
P = normalize( (1 − w_geo) · P_CNN + w_geo · P_geo )
consistency = 1 − ½ · Σ_c |P_CNN(c) − P_geo(c)|
```

固定 0.72/0.28 的融合在实测中会出问题：**极端的开怀大笑（眯眼、鼻孔张开）会被 CNN 判成"愤怒"**，
而几何层的 `cornerUp` 却能近乎 100% 确信这是笑。因此权重必须随两层各自的把握程度自适应。

`consistency` 既作为置信度的一项，也在界面上提示「两层是否一致」——CNN 被遮挡或侧脸干扰时，
几何层会拉住结果，反之亦然。**若模型加载失败，系统自动降级为纯几何引擎，仍可工作。**

### 6. 时序平滑与置信度（视频 / 摄像头）

镜头按约 100 ms 采样一帧，对每个人脸位置做指数滑动平均（α = 0.45）：

```
P̄_t = (1 − α)·P̄_{t−1} + α·P_t
conf  = 0.58·norm(max P̄) + 0.22·detScore + 0.20·consistency      （上限 0.97）
streak    = 连续同一情绪帧数       （≥ 3 帧 + conf ≥ 0.40 才触发换歌单）
stability = 最近 24 帧一致占比     （仅用于界面显示）
```

用 `streak` 而不是"窗口内一致占比"来判断是否换歌单：视频里情绪真的从"悲伤"切到"惊讶"时，
窗口一致率会被历史帧拖到 0.4 以下而误判为"不稳定"，连续帧计数则不受影响。
另外推荐请求有 1.5 s 冷却与并发锁，避免实时流下抖动导致反复请求在线接口。

### 7. 情绪坐标

由 7 类概率加权得到效价 / 唤醒度（Russell 环形模型），作为识别与推荐之间的中间表示：

```
V = Σ p_i · v_i ,  A = Σ p_i · a_i
```

## 四、歌曲推荐算法

### 1. 情绪 → 声学目标向量

把情绪映射到 5 维可计算特征空间（`valence` 效价、`energy` 能量、`danceability` 律动、
`acousticness` 原声度、`tempoNorm` 速度对数归一化）：

| 情绪 | valence | energy | dance | acoustic | BPM |
|---|---|---|---|---|---|
| 开心 | 0.92 | 0.82 | 0.80 | 0.22 | 122 |
| 悲伤 | 0.12 | 0.24 | 0.22 | 0.80 | 68 |
| 愤怒 | 0.18 | 0.95 | 0.56 | 0.08 | 148 |
| 惊讶 | 0.62 | 0.78 | 0.70 | 0.16 | 130 |
| 恐惧 | 0.14 | 0.50 | 0.20 | 0.60 | 92 |
| 厌恶 | 0.20 | 0.45 | 0.36 | 0.50 | 100 |
| 平静 | 0.50 | 0.42 | 0.50 | 0.60 | 90 |

`tempoNorm(bpm) = clamp( (ln bpm − ln 55) / (ln 190 − ln 55), 0, 1 )`

### 2. 三种调节策略

| 策略 | 目标向量 | 设计意图 |
|---|---|---|
| 共情陪伴 | `T = prototype(e)` | 顺着用户当前情绪，先被理解 |
| 温和疗愈 | `T = lerp(prototype(e), 向上情绪, 0.62)` | 从负面情绪向明亮舒缓过渡 |
| 提振激励 | `T = lerp(prototype(e), 高能原型, 0.58)` | 直接拉高能量与效价 |

向上情绪映射：悲伤/愤怒/恐惧 → 平静（calm 原型），厌恶 → 平静中性，惊讶 → 开心。

### 3. 打分函数（每首候选曲）

```
closeness = 1 − Σ w_i·|f_i − t_i| / Σ w_i     w = (energy 1.15, valence 1.50, dance 0.95, acoustic 0.70, tempo 0.85)
valFit    = exp( −(f_v − t_v)² / (2·0.24²) )
moodMatch = exp( −d²_circ / (2·0.46²) )        d_circ = ‖(V, A) − (V*, A*)‖   ← 情绪环形邻近度
affinity  = 1 − Σ|f_i − pref_i| / 5            ← 用户偏好向量（在线学习）
tempoFit  = exp( −(ln(f_bpm / t_bpm))² / (2·0.26²) )

score = 0.42·closeness + 0.18·valFit + 0.16·moodMatch + 0.14·affinity + 0.10·tempoFit
```

界面上的「匹配度 xx」就是 score×100，每条曲目下方的标签是其**得分构成的可读解释**。

### 4. 列表多样性（MMR 重排）

```
mmr = 0.78 · score − 0.22 · max_{s ∈ 已选} sim(candidate, s)
```

`sim` 取特征 L1 距离，并对同歌手 / 同曲风额外加相似度惩罚，避免整张歌单同质化。

### 5. 情绪弧线排序

疗愈 / 提振模式下，首曲取「与当前情绪最接近」的一首（先共情），其后按目标契合度排列，
形成「被理解 → 被带出」的过渡曲线；共情模式则直接按分数排序。

### 6. 反馈学习

```
pref ← clamp01( pref + η·(f_track − pref) )      η_like = 0.22, η_dislike = −0.20, η_skip = −0.05
```

喜欢 / 不喜欢 / 跳过即时更新偏好向量，写入 `localStorage`，下一次推荐立刻生效。

## 五、曲库与在线接口

### 本地曲库（8 首，离线可用）
`assets/audio/*.mp3`，由程序合成的器乐小品（无版权风险），每首自带合成时设定的真实声学参数：
阳光碎片（开心）、玻璃上的雨（悲伤）、铁脉搏（愤怒）、像素火花（惊讶）、
空心的光（恐惧）、酸涩大理石（厌恶）、纸月亮（平静）、软潮（舒缓）。

### 在线接口
| 接口 | 说明 | 状态 |
|---|---|---|
| iTunes Search API | 免密钥、支持跨域，返回 30 秒试听 m4a，曲库极大 | 默认启用 |
| Audius API | 开放、免密钥，返回整曲流媒体地址 | 备用（可在 `sources.js` 切换） |

按 7 类情绪各配 2–3 组检索词（如悲伤 → `sad acoustic songs` / `melancholy piano`）。

### 在线曲目特征怎么来（两段式）

1. **元数据先验**：曲风字典（Pop / Rock / Electronic / Classical…）＋ 关键词增量
   （`lofi` → 能量↓原声↑、`remix` → 律动↑、`acoustic` → 原声↑、`sad` → 效价↓…）。
2. **音频实测**（WebAudio，iTunes 试听文件允许跨域）：对试听片段做 FFT，
   - 能量：RMS 均值
   - 亮度：谱质心
   - 律动：谱通量本体密度（onset/s）
   - 速度：onset 包络自相关峰值（60–180 BPM 搜索）
   - 调式：Krumhansl-Kessler 调性模板相关（大调 → 效价上调，小调 → 效价下调）
3. 实测结果按 0.62/0.38 等比例**校正**元数据估计，界面用「实测 / 估计」标签明确标注来源。

## 七、隐私与技术要点

- 模型权重、曲目均在本地；**人脸图像只在内存中处理**，不上传、不落盘。
- 视频/摄像头用原生 `<video>` + Canvas 叠加绘制框与 68 点，`object-fit: contain` 保证坐标对齐；镜像预览时画布同步 `scaleX(-1)`。
- 摄像头 / 视频逐帧分析做了节流与互斥（一帧未完成不重叠推理），避免主线程卡顿。
- 兼容性：Chrome / Edge 最新版（WebGL 后端）；Safari 可能退回 CPU 后端，速度略慢。

## 八、已知局限

1. 表情分类对**侧脸、强逆光、口罩遮挡**敏感，建议正脸 + 均匀光照。
2. 在线曲目的声学特征部分依赖元数据估计，实测只覆盖能量/速度/律动/调性四类；
   效价（valence）无法从 30 秒片段完全还原。
3. 情绪→音乐的映射为经验性先验，个体差异较大，可通过「喜欢 / 不喜欢」逐步校准。
4. 演示人脸为 AI 生成，仅用于算法演示。
